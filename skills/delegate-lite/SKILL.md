# Delegate Lite

위임 비용보다 이득이 큰 독립 작업만 분담하라. 구현 책임과 최종 검증은 메인 에이전트가 맡아라.

## 조정 가능한 기본값

- 동시 서브에이전트: 최대 2개. 환경 제한이 더 작으면 그 제한을 따르라.
- 중첩 위임: 금지. 자식 에이전트에게 추가 에이전트를 생성하지 않도록 명시하라.
- 기본 권한: 조사·검토는 읽기 전용. 구현 작업은 명시한 파일 범위만 수정.
- 검토: 결과를 받은 후 메인이 통합 검토 1회.

## 실행 기능 확인

현재 환경에 노출된 실제 에이전트 생성·메시지·완료 확인 도구를 확인하라. 도구 이름을 가정하지 마라. 모델 이름만으로 지원 여부를 판단하지 마라.

기능이 없으면 지원하지 않음을 한 문장으로 밝히고 메인이 순차 수행하라. 역할극, 가짜 실행 로그, 임의의 API 호출로 실제 병렬 실행을 흉내 내지 마라. 사용자에게 별도 계정·키를 요구하거나 유료 에이전트 서비스를 자동 구성하지 마라.

## 분리 기준

다음이 모두 성립할 때만 병렬화하라:

1. 각 작업의 입력과 목표가 정해져 있다.
2. 다른 작업의 미완료 결과를 기다리지 않아도 된다.
3. 수정 파일·공유 상태가 충돌하지 않는다.
4. 결과를 메인이 확인하고 합칠 수 있다.

예: 메인이 구현하는 동안 에이전트 A는 읽기 전용 요구사항 누락 검토, B는 안정된 별도 모듈 테스트를 수행한다. 공용 타입이나 API 계약을 먼저 정해야 하는 구현은 그 결정을 마친 뒤 분리하라.

## 위임할 때 전달할 내용

```text
목표: 하나의 구체적인 작업
입력: 필요한 요구사항 ID, 파일 경로, 확정된 인터페이스
수정 범위: 읽기 전용 또는 수정 가능한 파일의 명시적 목록
제약: 범위 밖 파일 수정 금지, 다른 작업 덮어쓰기 금지, 추가 위임 금지
완료 조건: 관찰 가능한 결과
반환: 발견 사항, 변경 파일, 실행한 확인과 결과, 미해결 사항
```

필요한 맥락만 전달하라. 관련 없는 대화, 비밀키, 개인정보를 전달하지 마라. 작업 시간 제한이 있으면 함께 알려라.

## 통합

1. 독립 작업들을 실행하고 메인도 겹치지 않는 작업을 진행하라.
2. 환경의 완료 알림·대기 기능을 사용하고 불필요한 상태 반복 조회를 피하라.
3. 완료 보고를 받으면 실제 파일·변경·실행 결과를 확인하라. 보고만으로 성공을 확정하지 마라.
4. 충돌이 있으면 메인이 정리하고 관련 검증과 필수 사용자 흐름을 확인하라.
5. 작업 실패나 에이전트 생성 제한은 공개하고, 가능하면 메인이 이어서 완료하라. 완료되지 않은 결과를 완료로 취급하지 마라.
