# Frontend Preview

실제로 열어 비교할 수 있는 시안 비교 페이지를 먼저 만들고, 사용자가 명시적으로 선택한 방향으로 구현하라. 답변과 화면 문구는 사용자의 언어를 따르라.

## 첫 호출 시 채팅 입력 안내

- 이 세션에서 이 스킬을 처음 사용하거나 사용자가 사용법을 물으면, 본 작업 전에 목적·필요 입력과 아래 입력 예시를 채팅으로 짧게 안내하라. 저장소 문서 링크만 주고 끝내지 마라.
- 먼저 현재 요청과 아래 허용된 인계·산출물에서 입력을 확인하라. 이미 입력이 충분하면 '현재 [실제 파일/요구사항]으로 진행합니다. 다음 요청은 아래처럼 입력할 수 있습니다'라고 알리고 짧은 예시를 보여준 뒤 재입력을 기다리지 말고 요청한 작업을 진행하라.
- 부족한 입력이 있을 때만 필요한 항목을 표시한 예시를 제시하고 해당 입력을 받아라. 예시의 대괄호는 실제로 모르는 항목에만 남기고, 아는 경로·선택·시간은 채워라. 민감한 값은 안내 예시에 복사하지 마라.
- 반복 호출에서 같은 설명을 계속 출력하지 말고 작업에 집중하라. 입력 안내를 추가 승인 절차로 만들거나 질문 예산을 초기화하지 마라. 인터뷰·PRD의 필수 확인 질문은 기존 공동 질문 예산에 포함하라.

목적: 대표 화면의 UI 시안을 비교하는 페이지를 만들고 선택을 기다립니다.

필요 입력: 최신 PRD 또는 구체적인 화면 요구사항, 비교할 대표 화면. 선택: 시안 수·스타일·깊이.

입력 예시:

```text
$2-frontend-preview
PRD: [docs/PRD.md 또는 실제 경로]
대표 화면: [예: 목록 화면]
표준 모드로 시안 3개를 비교하는 페이지를 만들어줘.
내가 선택하기 전에는 서비스 전체 구현을 시작하지 마.
```

## 새 세션 재개와 프로젝트 파일

1. 현재 프로젝트의 docs/WORKFLOW_STATE.md(공통 상태), docs/WORKFLOW_SETTINGS.md(깊이·시간), 아래 지정한 현재 단계 인계 파일이 있으면 먼저 읽어라. 새 세션이 이전 대화를 안다고 가정하지 마라.
2. 공통 상태는 현재 단계·확정 문서 경로와 버전·다음 작업·미해결 문제·인계 경로만 담는 짧은 색인으로 유지하라. 과거 대화나 초기 결정의 상세 내용을 복사하지 마라. 링크된 문서를 재귀적으로 전부 읽지 말고 아래 단계별 범위 안에서만 읽어라.
3. 인계는 탐색용 기록이다. 지정된 실제 산출물·현재 코드·파일 변경 상태와 대조하고 오래된 내용은 갱신하라. 대화로만 확정됐던 내용은 사용자 확인 사실과 함께 산출물에 기록하되 초안·가정·미정·폐기된 제안을 확정 요구사항으로 승격하지 마라.
4. 시작·새 세션 재개·작업 종료·중단 또는 사용자 선택 대기 시 현재 단계 인계를 저장하라. 이미 끝난 작업과 사용한 질문 수, 명시적 선택, 사용자 확인 여부를 보존하여 같은 작업·질문·승인을 반복하지 마라. 남은 시간을 새 세션마다 180분으로 초기화하지 마라.
5. 인계 파일에는 대상 단계, 상태(진행 중/선택 대기/완료/막힘), 참조 가능한 파일과 버전, 완료·남은 작업, 실제 실행 명령·검증과 미확인 사항, 다음 행동을 짧게 기록하라. 다음 단계 인계에는 그 단계가 읽어도 되는 확정 결과·경로만 전달하라. 원본 인터뷰·폐기 초안·세션 대화록을 복사하지 마라.
6. 파일은 스킬 저장소나 설치 폴더가 아닌 실제 서비스 프로젝트에 작성하라. 사용자 지정 경로와 기존 문서 관례를 우선하고 실제 사용 경로를 색인에 기록하라. 필요한 파일만 만들고 기존 사용자의 변경을 덮어쓰지 마라. 파일 도구가 없으면 파일명과 내용을 제공하여 사용자가 다음 세션에 넘길 수 있게 하라.
7. 인계가 없으면 허용된 현재 파일로 최소 인계를 복원하고 확인한 사실과 미확인을 구분하라. 필수 입력이 없거나 서로 충돌하여 진행을 결정할 수 없을 때만 해당 내용에 한해 질문하라. 세션을 바꾸는 것 자체를 필수 절차로 만들지 마라.

### 이 단계의 참조 범위와 전달

- 현재 인계: docs/handoffs/2-frontend-preview.md.
- 입력: 최신 PRD, 기존 디자인 시스템·화면·자산, 이미 있는 docs/DESIGN_SELECTION.md. 초기 인터뷰나 폐기된 PRD 초안을 자동으로 열지 마라.
- 시안 비교 페이지 경로·실행 방법, 고정 후보 ID, 실제 확인한 동작, 사용자 선택 대기 여부를 현재 인계에 기록하라. 재개했을 때 선택 대기라면 같은 시안을 무조건 새로 만들지 말고 기존 결과를 제시하라.
- 사용자가 선택한 뒤 docs/DESIGN_SELECTION.md에 후보 ID·수정 메모·적용 범위·명시적 선택 근거를 저장하라. 미선택 또는 기본 선택을 확정 선택으로 기록하지 마라.
- docs/handoffs/3-build.md에는 PRD와 선택 결과의 경로·버전, 구현 시 유지할 디자인 규칙과 다음 행동을 기록하라. 선택 전에는 인계를 '선택 대기'로 남기고 구현 단계 완료로 처리하지 마라.

## 진행 깊이 선택

- 빠르게(quick), 표준(standard), 깊게(deep) 중 사용자가 지정한 모드를 적용하라. 기본은 표준이다.
- 작업 프로젝트의 docs/WORKFLOW_SETTINGS.md가 있으면 읽고 모드·남은 시간·개별 설정을 재사용하라. 현재 사용자의 명시적 요청을 가장 우선하라.
- 모드가 없으면 표준을 적용한다고 한 줄 알리고 진행하라. 사용자가 먼저 선택하겠다고 요청하면 세 모드 중 선택을 받아라. 이미 정한 모드를 반복 질문하지 마라.
- 선택·변경된 값은 파일 도구가 있으면 docs/WORKFLOW_SETTINGS.md에 짧게 기록하라. 파일이 없으면 새로 만들되 기존 설정의 다른 항목은 보존하라. 파일 도구가 없으면 대화에 기록하라.
- 아래 숫자는 자연어 기본값과 목표 예산이다. 자동 타이머나 프로그램의 강제 제한이 아니다. 실제 남은 시간을 확인할 수 없으면 사용자에게 받은 시간을 사용하고 추정임을 표시하라.
- 깊이를 줄여도 원문 필수 기능, 고정 ID, 명시적인 시안 선택, 실제 검증의 정직성은 유지하라. 시간 부족 때문에 필수 기능을 조용히 제외하지 마라.

| 모드 | 기본 시안 수 | 대표 화면의 완성도 | 3시간 시험의 목표 시간 |
| --- | --- | --- | --- |
| 빠르게 | 2개 | 구조·핵심 스타일 비교, 핵심 동작 최소 구현 | 5~8분 |
| 표준 | 3개 | 대표 화면의 실제 UI·모바일 보기·선택 기능 | 10~15분 |
| 깊게 | 4개 | 대표 화면의 시각적 완성도와 주요 상태·상호작용 비교 | 20~30분 |

사용자가 시안 수를 지정하면 해당 수를 우선하라. 5~6개도 지정 가능하며 6개는 권장 상한일 뿐 기술적 제한이 아니다. 그 이상도 요청할 수 있으나 생성·비교 비용이 늘어남을 짧게 알리고 대표 화면 범위를 줄이는 방법을 제안하라. 임의로 요청한 개수를 줄이지 마라. 어떤 모드도 서비스를 시안 수만큼 전체 구현하는 뜻이 아니다. 시안 선택에 사용자가 쓰는 시간도 전체 시험 시간에 포함된다.

## 조정 가능한 기본값 — 표준 모드 기준

- 시안: 3개. 사용자가 개수나 디자인을 지정하면 우선하라.
- 비교 범위: 대표 화면 1개와 핵심 상호작용 1개. 전체 서비스를 세 번 구현하지 마라.
- 비교 화면: 나란히 볼 수 있는 요약 카드와 시안별 확대 보기, 데스크톱·모바일 전환, 선택 버튼.
- 산출물: 프로젝트에 맞는 미리보기 경로 또는 previews/frontend/index.html, 선택 기록은 docs/DESIGN_SELECTION.md.
- 확인: 시안 제작 후 선택을 기다리는 지점 1회. 이미 명시된 선택을 다시 승인받지 마라.

## 요구사항 고정

1. PRD, 기존 화면·컴포넌트, 디자인 자산과 실행 방법을 읽어라. 사용자·핵심 기능·데이터는 시안마다 동일하게 유지하라.
2. 기존 디자인 시스템이 있으면 그 안에서 변형하라. 새 라이브러리나 이미지를 만들지 않고 HTML/CSS·기존 컴포넌트로 충분하면 그대로 사용하라.
3. 시안 A/B/C의 차이를 정보 배치, 밀도, 타이포그래피, 색상 등 구체적인 축으로 정하라. 기능이 더 많은 시안을 유리하게 만들지 마라.

## 비교 페이지 구현

- 실제 렌더링되는 웹페이지를 만들어라. 글이나 이미지 설명만으로 대체하지 마라.
- 모든 후보에 같은 현실적인 샘플 데이터를 사용하라. 미리보기용 데이터와 미연결 기능은 표시하라.
- 시안별 고정 ID, 이름, 차이 설명을 짧게 붙여라. 선택·확대·모바일 전환을 키보드로도 사용할 수 있게 하라.
- 대표 상호작용이 가능하게 구현하고, 비교 페이지의 선택 버튼과 실제 서비스 동작 버튼을 구분하라.
- 선택하면 해당 카드에 선택 상태를 표시하고, 선택 ID와 수정 메모를 복사하거나 다운로드할 수 있게 하라. 새로고침 시 선택이 유지되도록 가능한 경우 로컬 저장을 사용하라.
- 화면에서 클릭한 결과가 에이전트에 자동 전달된다고 가정하지 마라. 선택 정보를 읽을 연결 수단이 없으면 사용자가 채팅에 선택 ID·메모를 보내도록 안내하라.
- 파일 도구와 실행 환경으로 페이지를 실제로 제공할 수 없으면 한계를 설명하라. 존재하지 않는 미리보기 주소나 작동하지 않는 선택 기능을 완료로 보고하지 마라.

## 제시와 선택

1. 비교 페이지가 열리는지, 후보·전환·선택 동작이 정상인지 가능한 도구로 확인하라. 실제 확인한 것과 미확인을 구분하라.
2. 페이지 링크 또는 실행 방법, 후보별 차이, 선택 방법을 간결하게 제공하라.
3. 이 단계에서 사용자의 선택을 기다려라. 기본 선택값이나 시간 경과를 사용자 선택으로 취급하지 마라.
4. 'B로 진행', 'A 배치와 C 색상을 조합' 같은 명시적인 선택을 기록하라. 큰 해석 차이가 있을 때만 한 가지 질문으로 확인하라.

## 선택 후 구현

- 선택 ID, 반영할 수정 메모, 적용 범위를 docs/DESIGN_SELECTION.md에 저장하라. 기준이 된 시안 ID를 변경하지 마라.
- 선택한 시안을 실제 서비스에 적용하라. 샘플 데이터는 PRD에서 요구한 실제 상태·저장·API에 연결하고 로딩·빈 상태·오류 상태를 구현하라.
- 여러 화면으로 확장할 때 선택한 타이포그래피·간격·색상·컴포넌트 규칙을 유지하라.
- 원래 요구사항과 선택한 디자인에 맞게 검증하고 구현·미확인 부분을 보고하라. 이후 구현 절차에 3-build 스킬을 사용할 수 있으나 실제 선택 없이 자동 진행하지 마라.

## 완료 기준

선택 전에는 비교 페이지와 선택 방법이 제공되어야 한다. 전체 완료는 사용자 선택이 기록되고 실제 서비스에 반영되어 검증된 때다. 비교 페이지 생성만 끝난 상태와 서비스 적용 완료 상태를 구분하라.
