# Deep Interview

짧은 인터뷰로 구현에 필요한 결정만 정리하라. 답변은 사용자의 언어로 작성하라.

## 진행 깊이 선택

- 빠르게(quick), 표준(standard), 깊게(deep) 중 사용자가 지정한 모드를 적용하라. 기본은 표준이다.
- 작업 프로젝트의 docs/WORKFLOW_SETTINGS.md가 있으면 읽고 모드·남은 시간·개별 설정을 재사용하라. 현재 사용자의 명시적 요청을 가장 우선하라.
- 모드가 없으면 표준을 적용한다고 한 줄 알리고 진행하라. 사용자가 먼저 선택하겠다고 요청하면 세 모드 중 선택을 받아라. 이미 정한 모드를 반복 질문하지 마라.
- 선택·변경된 값은 파일 도구가 있으면 docs/WORKFLOW_SETTINGS.md에 짧게 기록하라. 파일이 없으면 새로 만들되 기존 설정의 다른 항목은 보존하라. 파일 도구가 없으면 대화에 기록하라.
- 아래 숫자는 자연어 기본값과 목표 예산이다. 자동 타이머나 프로그램의 강제 제한이 아니다. 실제 남은 시간을 확인할 수 없으면 사용자에게 받은 시간을 사용하고 추정임을 표시하라.
- 깊이를 줄여도 원문 필수 기능, 고정 ID, 명시적인 시안 선택, 실제 검증의 정직성은 유지하라. 시간 부족 때문에 필수 기능을 조용히 제외하지 마라.

| 모드 | 질문 예산 | 탐색 범위 | 3시간 시험의 목표 시간 |
| --- | --- | --- | --- |
| 빠르게 | 0~1개 | 구현을 막는 결정만 | 0~3분 |
| 표준 | 최대 3개 | 목표·범위·제약·완료 기준의 핵심 모호함 | 3~7분 |
| 깊게 | 최대 8개 | 숨은 가정, 요구사항 충돌, 대안의 선택 기준, 주요 예외·데이터 흐름 | 10~20분 |

질문은 한 번에 하나씩 하고 이미 명확하면 예산을 채우지 말고 종료하라. 질문 예산은 1-prd와 합산하라. 깊게 모드는 장기 운영·사업·보안 인터뷰를 자동 추가하는 뜻이 아니다. 사용자가 '질문 최대 5개'처럼 지정하면 그 값을 우선하라.

## 조정 가능한 기본값 — 표준 모드 기준

- 질문 예산: 표준은 현재 요구사항 정리 과정 전체에서 최대 3개. 다른 모드는 위 표를 적용.
- 진행 방식: 한 번에 질문 1개, 필요할 때 선택지 2~3개와 자유 입력 제공.
- 결과 분량: 약 30줄 이내.
- 사용자 설정을 이 기본값보다 우선하라. 이미 답한 질문은 예산에서 다시 시작하지 마라.

## 진행

1. 문제 설명, 기존 명세와 관련 코드를 먼저 읽어라. 거기서 알 수 있는 것은 묻지 마라.
2. 목표 사용자, 핵심 행동, 필수 범위, 기술·시간 제약, 완료 기준 중 가장 큰 불확실성을 골라라.
3. 구현 방향이 실제로 달라지는 질문만 하라. 답변을 기다린 뒤 다음 결정을 진행하라.
4. 사소하고 되돌릴 수 있는 사항은 가정으로 표시하라. 요구사항에 없는 기능을 추가하지 마라.
5. 설정된 질문 예산 전에 충분히 명확해지면 종료하라. 예산이 끝나도 필수 요구사항끼리 충돌하면 그 충돌을 명시하고 관련 구현은 보류하라.

## 결과

다음 항목을 간결하게 정리하라:

- 목표와 사용자
- 반드시 구현할 기능
- 이번에 제외할 기능
- 시간·기술·데이터 제약
- 관찰 가능한 완료 기준
- 가정과 남은 질문

PRD 요청이 있으면 이 결과를 1-prd의 입력으로 넘겨라. 인터뷰만 요청받았다면 여기서 끝내라. 구현은 구현 요청이 있을 때 진행하라.

## 범위

긴 점수 계산, 상태 관리용 JSON, 사업 전략 인터뷰는 기본으로 생성하지 마라. 인증·권한 등 요구된 조건은 보존하되 별도 보안 설계 문서를 자동 생성하지 마라.
