# Delegate

위임 비용보다 이득이 큰 독립 작업만 분담하라. 구현 책임과 최종 검증은 메인 에이전트가 맡아라.

## 첫 호출 시 채팅 입력 안내

- 이 세션에서 이 스킬을 처음 사용하거나 사용자가 사용법을 물으면, 본 작업 전에 목적·필요 입력과 아래 입력 예시를 채팅으로 짧게 안내하라. 저장소 문서 링크만 주고 끝내지 마라.
- 먼저 현재 요청과 아래 허용된 인계·산출물에서 입력을 확인하라. 이미 입력이 충분하면 '현재 [실제 파일/요구사항]으로 진행합니다. 다음 요청은 아래처럼 입력할 수 있습니다'라고 알리고 짧은 예시를 보여준 뒤 재입력을 기다리지 말고 요청한 작업을 진행하라.
- 부족한 입력이 있을 때만 필요한 항목을 표시한 예시를 제시하고 해당 입력을 받아라. 예시의 대괄호는 실제로 모르는 항목에만 남기고, 아는 경로·선택·시간은 채워라. 민감한 값은 안내 예시에 복사하지 마라.
- 반복 호출에서 같은 설명을 계속 출력하지 말고 작업에 집중하라. 입력 안내를 추가 승인 절차로 만들거나 질문 예산을 초기화하지 마라. 인터뷰·PRD의 필수 확인 질문은 기존 공동 질문 예산에 포함하라.

목적: 서로 독립적인 작업을 실제 서브에이전트에 분담합니다.

필요 입력: 분담할 작업과 부모 단계, 입력 자료, 읽기 전용/수정 가능한 범위. 기본 모델: gpt-6.1-sol, 기본 추론 수준: medium, 선택 가능: medium/high, 표준·깊게 동시 한도: 최대 3개(메인 제외). 선택: 작업별 추론 수준·한도·모델·깊이 재지정.

입력 예시:

```text
$4-delegate
gpt-6.1-sol 서브에이전트를 동시에 최대 3개 사용해줘.
추론 수준은 기본 medium, 복잡한 핵심 로직·검토는 high로 설정해줘.
입력: [PRD 및 관련 파일 경로]
먼저 인터페이스와 담당 파일을 정한 뒤 독립 작업을 나눠줘.
A: 프론트엔드, B: 핵심 로직·데이터, C: 읽기 전용 요구사항·테스트 검토.
메인은 조정·통합·최종 검증을 맡아줘.
모델 지정이나 동시 실행이 지원되지 않으면 실제 제한을 알려줘.
```

## 새 세션 재개와 프로젝트 파일

1. 현재 프로젝트의 docs/WORKFLOW_STATE.md(공통 상태), docs/WORKFLOW_SETTINGS.md(깊이·시간), 아래 지정한 현재 단계 인계 파일이 있으면 먼저 읽어라. 새 세션이 이전 대화를 안다고 가정하지 마라.
2. 공통 상태는 현재 단계·확정 문서 경로와 버전·다음 작업·미해결 문제·인계 경로만 담는 짧은 색인으로 유지하라. 과거 대화나 초기 결정의 상세 내용을 복사하지 마라. 링크된 문서를 재귀적으로 전부 읽지 말고 아래 단계별 범위 안에서만 읽어라.
3. 인계는 탐색용 기록이다. 지정된 실제 산출물·현재 코드·파일 변경 상태와 대조하고 오래된 내용은 갱신하라. 대화로만 확정됐던 내용은 사용자 확인 사실과 함께 산출물에 기록하되 초안·가정·미정·폐기된 제안을 확정 요구사항으로 승격하지 마라.
4. 시작·새 세션 재개·작업 종료·중단 또는 사용자 선택 대기 시 현재 단계 인계를 저장하라. 이미 끝난 작업과 사용한 질문 수, 명시적 선택, 사용자 확인 여부를 보존하여 같은 작업·질문·승인을 반복하지 마라. 남은 시간을 새 세션마다 180분으로 초기화하지 마라.
5. 인계 파일에는 대상 단계, 상태(진행 중/선택 대기/완료/막힘), 참조 가능한 파일과 버전, 완료·남은 작업, 실제 실행 명령·검증과 미확인 사항, 다음 행동을 짧게 기록하라. 다음 단계 인계에는 그 단계가 읽어도 되는 확정 결과·경로만 전달하라. 원본 인터뷰·폐기 초안·세션 대화록을 복사하지 마라.
6. 파일은 스킬 저장소나 설치 폴더가 아닌 실제 서비스 프로젝트에 작성하라. 사용자 지정 경로와 기존 문서 관례를 우선하고 실제 사용 경로를 색인에 기록하라. 필요한 파일만 만들고 기존 사용자의 변경을 덮어쓰지 마라. 파일 도구가 없으면 파일명과 내용을 제공하여 사용자가 다음 세션에 넘길 수 있게 하라.
7. 인계가 없으면 허용된 현재 파일로 최소 인계를 복원하고 확인한 사실과 미확인을 구분하라. 필수 입력이 없거나 서로 충돌하여 진행을 결정할 수 없을 때만 해당 내용에 한해 질문하라. 세션을 바꾸는 것 자체를 필수 절차로 만들지 마라.

### 이 단계의 참조 범위와 전달

- 현재 인계: 메인 조정자가 관리하는 docs/handoffs/4-delegate.md. 이 스킬은 3번 다음의 필수 단계가 아니라 현재 작업을 보조한다.
- 메인은 부모 작업에 허용된 자료 중 해당 작업에 필요한 요구사항 ID·계약·파일만 전달하라. 번호상 이전 스킬의 결과를 전부 전달하지 마라. 5-manual-review를 보조하는 에이전트에도 5번과 같은 참조 제한을 적용하라.
- 작업별 ID, 목표·담당 파일·입력 버전, 에이전트 상태, 결과·미완료를 현재 인계에 기록하라. 새 세션에서 기존 에이전트 핸들이 유효하다고 가정하지 말고 실제 파일·결과를 확인한 뒤 재사용 또는 재실행을 결정하라.
- 결과는 docs/DELEGATION_REPORT.md 또는 프로젝트의 기존 작업별 보고 경로에 저장하라. 발견 사항과 실제 검증을 구분하라. 메인이 확인한 결과만 부모 단계 인계에 반영하라.
- 병렬 에이전트는 공통 상태·다른 단계 인계를 직접 덮어쓰지 말고 메인에 보고하라. 메인이 관련 항목을 병합하여 부모 작업의 진행·설정·미완료 정보를 보존하라.

## 진행 깊이 선택

- 빠르게(quick), 표준(standard), 깊게(deep) 중 사용자가 지정한 모드를 적용하라. 기본은 표준이다.
- 작업 프로젝트의 docs/WORKFLOW_SETTINGS.md가 있으면 읽고 모드·남은 시간·개별 설정을 재사용하라. 현재 사용자의 명시적 요청을 가장 우선하라.
- 모드가 없으면 표준을 적용한다고 한 줄 알리고 진행하라. 사용자가 먼저 선택하겠다고 요청하면 세 모드 중 선택을 받아라. 이미 정한 모드를 반복 질문하지 마라.
- 선택·변경된 값은 파일 도구가 있으면 docs/WORKFLOW_SETTINGS.md에 짧게 기록하라. 파일이 없으면 새로 만들되 기존 설정의 다른 항목은 보존하라. 파일 도구가 없으면 대화에 기록하라.
- 아래 숫자는 자연어 기본값과 목표 예산이다. 자동 타이머나 프로그램의 강제 제한이 아니다. 실제 남은 시간을 확인할 수 없으면 사용자에게 받은 시간을 사용하고 추정임을 표시하라.
- 깊이를 줄여도 원문 필수 기능, 고정 ID, 명시적인 시안 선택, 실제 검증의 정직성은 유지하라. 시간 부족 때문에 필수 기능을 조용히 제외하지 마라.

| 모드 | 기본 동시 에이전트 수 | 기본 분담 |
| --- | --- | --- |
| 빠르게 | 0개 | 메인 순차 수행, 명시 요청 시 1개 |
| 표준 | 최대 3개 | 파일 범위가 분리된 구현·로직·읽기 전용 검토, 메인이 조정·통합 |
| 깊게 | 최대 3개 | 같은 동시 한도 안에서 계약·예외·검증과 통합 검토를 더 깊게 |

개별 동시 한도 지정은 모드보다 우선하며 환경의 실제 한도를 넘지 마라. 모든 모드에서 중첩 위임을 금지하고 파일 충돌을 피하라. 기본 한도는 전체 서브에이전트 수가 아니라 동시에 실행되는 수이다. 짧은 작업은 위임 준비·통합 비용이 더 클 수 있으므로 병렬화를 강제하지 마라.

## 조정 가능한 기본값 — 표준 모드 기준

- 동시 서브에이전트: 표준·깊게 최대 3개, 메인은 별도이다. 빠르게는 기본 0개이며 명시적 동시 수 요청이 모드 기본값보다 우선한다. 명시적 설정과 환경 제한을 우선하라.
- 우선 모델: GPT 6.1 Sol. 현재 실행 도구가 지원하는 정확한 모델 ID를 확인하고 `gpt-6.1-sol`이 있으면 사용하라.
- 추론 수준: 기본 medium, 작업별 medium 또는 high만 사용. 복잡한 로직·예외 검토에 high를 선택할 수 있으며 사용자가 지정한 작업별 값을 우선하라.
- 중첩 위임: 금지. 자식 에이전트에게 추가 에이전트를 생성하지 않도록 명시하라.
- 기본 권한: 조사·검토는 읽기 전용. 구현 작업은 명시한 파일 범위만 수정.
- 검토: 결과를 받은 후 메인이 통합 검토 1회.

## 실행 기능 확인

현재 환경에 노출된 실제 에이전트 생성·메시지·완료 확인 도구를 확인하라. 도구 이름을 가정하지 마라. 모델 이름만으로 지원 여부를 판단하지 마라.

기능이 없으면 지원하지 않음을 한 문장으로 밝히고 메인이 순차 수행하라. 역할극, 가짜 실행 로그, 임의의 API 호출로 실제 병렬 실행을 흉내 내지 마라. 사용자에게 별도 계정·키를 요구하거나 유료 에이전트 서비스를 자동 구성하지 마라.

## 모델·추론 수준 지정과 3개 동시 실행

1. 실제 에이전트 도구의 모델 목록·모델 선택·추론 수준 선택 인자·동시 한도를 확인하라. `gpt-6.1-sol`은 요청 모델 ID이며 환경의 지원을 가정하지 마라. 같은 표시 이름만 보고 다른 모델로 치환하지 마라.
2. 모델을 고를 수 있으면 각 서브에이전트 생성에 지원되는 모델 인자를 명시하라. 추론 수준은 기본 medium, 사용자가 high를 지정했거나 복잡한 핵심 로직·검토라면 high를 선택하라. reasoning_effort 같은 인자가 실제로 있을 때만 그 스키마에 맞춰 지정하라. 허용된 범위는 medium/high이며 low·xhigh 등 다른 값으로 임의 변경하지 마라. 인자 이름과 모델 상속 조건은 실제 도구 스키마를 따르라. 모델·추론 선택이 없더라도 요청한 모델 및 medium/high 상속이 환경에서 확인되는 경우에만 그 사실을 기록하고 사용하라. 단순히 프롬프트에 더 깊게 생각하라고 적는 것을 런타임 추론 설정과 동일하게 취급하지 마라.
3. 지정 모델·추론 수준을 쓸 수 없거나 실제 설정을 확인할 수 없으면 먼저 사실을 알리고, 다른 모델·추론 수준을 사용자의 선택 없이 요청한 설정인 것처럼 실행·보고하지 마라. 별도 API·계정·도구를 임의로 구성하여 우회하지 마라. 가능한 부모 작업은 메인이 계속 수행하라.
4. 독립 작업이 3개 있으면 생성 호출들을 한 번에 시작하고 실제로 동시 진행하게 하라. 하나가 끝난 뒤 다음을 생성하는 순차 실행을 3개 병렬 실행이라고 보고하지 마라. 작업이 1~2개뿐이면 숫자를 채우기 위한 불필요한 작업을 만들지 마라.
5. 동시 수는 활성 서브에이전트 수이며 메인을 포함하지 않는다. 메인 1개 + 서브 3개면 총 4개의 에이전트가 관여한다. 환경 한도가 더 낮으면 가능한 수만 동시 실행하고 나머지는 대기열로 처리하되 제한과 실제 동시 수를 알려라.
6. docs/WORKFLOW_SETTINGS.md에 요청 모델·기본 추론 수준(medium)·작업별 high 지정·동시 한도(3, 메인 제외)를 기록하라. 현재 단계 인계·보고에는 요청 모델·추론 수준, 도구에서 지정/확인한 모델·추론 수준 또는 확인 불가, 작업별 ID·상태, 실제 동시 수와 제한을 남겨라. 새 세션에서 이 설정을 재사용하되 런타임 지원을 다시 확인하라.

3개 분담 예시:

| 담당 | 작업 예시 | 추론 수준 예시 | 충돌 방지 |
| --- | --- | --- | --- |
| A | 화면·컴포넌트 구현 | medium | 지정된 프론트엔드 파일만 수정 |
| B | 핵심 로직·데이터 처리 | 복잡하면 high, 일반 작업 medium | A와 분리된 로직 파일만 수정 |
| C | 요구사항 대조·안정된 기능 테스트 점검 | 복잡한 예외 검토 high, 일반 점검 medium | 기본 읽기 전용, 기준 버전과 미확인 표시 |
| 메인 | 계약 확정·진행 조정·결과 통합·최종 검증 | 현재 메인 설정 유지 | 공통 타입·설정·인계 파일의 변경 조정 |

이 역할을 모든 프로젝트에 강제하지 마라. API·공용 타입이 미정이면 메인이 먼저 계약을 확정하라. 변경 중인 코드에 대한 검토·테스트는 확인한 버전을 기록하고 최종 통합 후 필요한 검증을 다시 하라. 모든 자식에게 중첩 위임 금지와 담당 범위를 전달하라.

## 분리 기준

다음이 모두 성립할 때만 병렬화하라:

1. 각 작업의 입력과 목표가 정해져 있다.
2. 다른 작업의 미완료 결과를 기다리지 않아도 된다.
3. 수정 파일·공유 상태가 충돌하지 않는다.
4. 결과를 메인이 확인하고 합칠 수 있다.

예: 메인이 구현하는 동안 에이전트 A는 읽기 전용 요구사항 누락 검토, B는 안정된 별도 모듈 테스트를 수행한다. 공용 타입이나 API 계약을 먼저 정해야 하는 구현은 그 결정을 마친 뒤 분리하라.

## 위임할 때 전달할 내용

```text
요청 모델: gpt-6.1-sol (실제 도구 지원 확인 후 생성 인자로 지정)
요청 추론 수준: medium 또는 high (기본 medium, 실제 선택 인자 지원 확인)
목표: 하나의 구체적인 작업
입력: 필요한 요구사항 ID, 파일 경로, 확정된 인터페이스
수정 범위: 읽기 전용 또는 수정 가능한 파일의 명시적 목록
제약: 범위 밖 파일 수정 금지, 다른 작업 덮어쓰기 금지, 추가 위임 금지
완료 조건: 관찰 가능한 결과
반환: 발견 사항, 변경 파일, 실행한 확인과 결과, 미해결 사항
```

필요한 맥락만 전달하라. 관련 없는 대화, 비밀키, 개인정보를 전달하지 마라. 작업 시간 제한이 있으면 함께 알려라.

## 통합

1. 독립 작업들을 실행하고 메인도 겹치지 않는 작업을 진행하라.
2. 환경의 완료 알림·대기 기능을 사용하고 불필요한 상태 반복 조회를 피하라.
3. 완료 보고를 받으면 실제 파일·변경·실행 결과를 확인하라. 보고만으로 성공을 확정하지 마라.
4. 충돌이 있으면 메인이 정리하고 관련 검증과 필수 사용자 흐름을 확인하라.
5. 작업 실패나 에이전트 생성 제한은 공개하고, 가능하면 메인이 이어서 완료하라. 완료되지 않은 결과를 완료로 취급하지 마라.
