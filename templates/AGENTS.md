# 작업 규칙

세션 내내 적용한다. 단계별 절차는 스킬에 있다: `$1-kickoff` → `$2-build` → `$3-finish`.

## 우선순위

과제 원문(README·안내) > 업무 담당자 답변 > 이 규칙. 필수 파일명·경로·기술 스택은 과제 원문을 따른다. 서로 충돌하면 임의로 정하지 말고 사람에게 알린다.

## 게이트

통과하기 전에는 다음 단계로 넘어가지 않는다. 시간이 부족하다는 이유로 건너뛰지 않는다.

- **G1 데이터:** 제공 데이터를 스크립트로 세어 `docs/DATA_PROFILE.md`에 남기기 전에는 설계하지 않는다.
- **G2 설계:** `docs/DECISIONS.md`의 "설계 고정"에 기준 데이터, 결과별 예상 범위와 산식, 숫자 완료 조건, 멈춤 조건을 적고 사람의 OK를 받기 전에는 구현하지 않는다.
- **G3 규모:** 핵심 로직을 실행하면 바로 실제 결과 수와 분포를 예상 범위와 비교해 출력한다. 범위를 벗어나면 API·화면으로 넘어가지 말고 멈춰서 원인과 함께 보고한다. 범위를 바꾸려면 근거를 D 항목으로 남기고 사람의 OK를 받는다.
- **G4 증거:** 이번 턴에 명령을 실행하고 출력을 읽기 전에는 완료·통과·수정됨이라고 말하지 않는다. 서브에이전트 보고는 diff와 직접 실행으로 확인한다. 확인하지 못한 것은 미확인이라고 쓴다.

## 시간

타이머를 볼 수 없으니 남은 시간을 추측하지 않는다. 게이트를 넘을 때 사람에게 한 줄로 묻되, 방금 들었으면 다시 묻지 않는다. 시간이 모자라면 선택 기능, UI 장식 순으로 줄인다. 필수 요구사항을 조용히 빼지 않는다.

## 서버

- 서버는 사람이 `server` 터미널에서 실행한다. 직접 띄우지 말고 실행 명령 한 줄을 알려준다. 명령에는 `2>&1 | tee logs/server.log`를 붙인다.
- 확인은 `curl`과 `logs/server.log`로 한다. 재시작이 필요하면 사람에게 요청한다.
- 서버는 `0.0.0.0`에 바인딩한다. 미리보기는 플랫폼 프록시 주소로 열리므로 프론트의 API 호출은 상대 경로로 쓰고, 가능하면 한 포트로 서빙한다.

## 기록

- 결정은 `docs/DECISIONS.md`, 요구사항·작업·검증 결과·실수는 `docs/TASKS.md`에 남긴다. 대화에만 남기지 않는다.
- 검수를 받거나 AI 제안을 받아들이거나 버릴 때는 그 자리에서 `docs/AI_LOG.md`에 요청 원문, 처리, 근거를 적는다. 나중에 기억으로 채우지 않는다.
- 제출 문서에는 실제로 한 일과 근거가 있는 것만 쓴다. 후속 서술형은 제출물과 작업 기록을 바탕으로 출제된다.
- 게이트 통과와 작업 완료 때마다 로컬 커밋한다. 메시지에 D·R ID를 넣는다.
- 설계나 로직이 틀렸음을 발견하면 숨기지 말고 `docs/TASKS.md`의 "실수와 수정"에 적는다. 사소한 명령 실패는 적지 않는다.

## 위임

서브에이전트는 세션당 최대 2개다(메인 제외). 절차는 `$2-build`를 따른다. 설계와 핵심 로직은 메인이 맡는다.

## 금지

- 문제·파일·결과물의 외부 전송과 git push
- 개인 API 키·구독, 외부 AI 서비스·모델 연결, Computer Use
- 플랫폼 관리 설정, 감독·연결 프로세스의 수정·종료, 차단 기능의 우회
- 외부 코드로 결과물을 통째로 대체하기. 일부를 참고하면 출처를 남긴다.

막히면 우회하지 말고 사람에게 알린다. 플랫폼 오류는 사람이 '문제 신고'로 접수한다.
