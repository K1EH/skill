# AI Dev Skills

저장소: https://github.com/K1EH/skill

**설치 및 시험 활용 방법: [USAGE.md](USAGE.md)** · **깊이·시간 선택: [SETTINGS.md](SETTINGS.md)** · **세션 인계: [SESSION_GUIDE.md](SESSION_GUIDE.md)**

제한된 시간에 작은 서비스를 만드는 한국어 경량 에이전트 스킬 6종입니다. 요구사항 정리부터 PRD, 구현·검증, 선택적 병렬 작업까지 필요한 부분만 사용합니다.

Superpowers 등의 공개 스킬에서 아이디어를 가져와 축약·재작성한 독립 구성입니다. 공식 Superpowers 경량판이 아닙니다. [출처와 라이선스](THIRD_PARTY_NOTICES.md)를 확인하세요.

## 스킬 사용 순서

0. deep-interview — 모호한 요구사항 정리, 필요할 때만 사용
1. prd — 요구사항과 완료 조건 작성
2. frontend-preview — UI 시안 비교 및 선택, 필요할 때만 사용
3. build — 실제 서비스 구현·검증
4. delegate — build 중 독립 작업 분담, 선택 사용
5. manual-review — 번호 매뉴얼로 검수하고 수정 반영

표시명은 위와 같고 실제 폴더·호출 이름에는 숫자와 하이픈을 사용합니다. 예: `$0-deep-interview`, `$1-prd`. 번호는 흐름을 찾기 위한 것으로, 4번은 구현이 끝난 뒤의 필수 단계가 아니라 3번과 함께 쓸 수 있는 보조 스킬입니다.

## 스킬

| 스킬 | 역할 | 기본 제한 |
| --- | --- | --- |
| [0-deep-interview](skills/0-deep-interview/SKILL.md) | 가장 큰 불확실성부터 질문하여 요구사항 정리 | 표준 최대 6개, 선택지·장단점·정책·예외 확인 |
| [1-prd](skills/1-prd/SKILL.md) | 기능과 관찰 가능한 완료 조건을 PRD로 작성 | 약 100줄, 필수·선택 구분 |
| [2-frontend-preview](skills/2-frontend-preview/SKILL.md) | 정보 구조·핵심 흐름·상태가 다른 완성도 높은 UI 비교 → 선택 → 구현 계약 | 표준 3개, 대표 화면+상세/편집·모바일·상태 비교 |
| [3-build](skills/3-build/SKILL.md) | 작업 계획 → 필수 기능 구현 → 통합 검증 | 보통 4~8개 작업, 최종 검토 1회 |
| [4-delegate](skills/4-delegate/SKILL.md) | 독립 작업만 서브에이전트에 분담 | GPT 6.1 Sol, medium/high, 동시 최대 3개, 메인 제외 |
| [5-manual-review](skills/5-manual-review/SKILL.md) | 번호 매뉴얼 작성 → 항목별 피드백 → 코드·문서 수정 | P03-02처럼 고정 페이지·항목 ID |

인터뷰 → PRD → 선택적 UI 시안 비교 → 구현·검증 → 사용자 매뉴얼 검수 순서로 사용합니다. 명세가 충분하면 인터뷰를 건너뛰어도 됩니다. 서브에이전트는 필요할 때만 사용합니다. 질문 예산은 인터뷰와 PRD가 공유하며 같은 질문을 반복하지 않습니다.

각 스킬을 새 세션에서 처음 호출하면 필요한 입력과 복사 가능한 요청 예시를 채팅으로 안내합니다. 이미 요청·인계에 입력이 충분하면 재입력을 요구하지 않고 이어갑니다.

## 가져오기

각 `skills/<스킬 이름>/` 폴더가 독립 단위입니다. `SKILL.md`, `LICENSE`, `agents/openai.yaml`을 함께 복사하세요. 의존 라이브러리, 실행 스크립트, 외부 API 키는 없습니다.

- 플랫폼이 GitHub 스킬 가져오기를 제공하면 저장소와 원하는 스킬 경로를 지정하세요.
- 에이전트가 로컬 스킬 폴더를 지원하면 해당 에이전트가 안내하는 경로에 원하는 폴더를 복사하세요.
- 자동 검색 기능이 없으면 아래처럼 `SKILL.md` 경로를 명시하고 읽어서 따르도록 요청할 수 있습니다.

```text
skills/1-prd/SKILL.md를 읽고 따라줘.
아래 요구사항을 MVP PRD로 정리해줘. 구현은 하지 마.
[요구사항]
```

플랫폼마다 스킬 검색 경로, 호출 표기, YAML 메타데이터 지원이 다릅니다. `agents/openai.yaml`은 선택적인 UI 메타데이터입니다. 지원하지 않는 환경에서는 `SKILL.md`만 읽어도 절차를 사용할 수 있습니다.

COFA Probe의 GitHub 가져오기 방식과 실제 서브에이전트 지원은 응시 환경에서 별도 확인해야 합니다. 이 저장소는 Probe의 공식 플러그인이 아닙니다. GPT 모델을 선택하거나 스킬을 설치하는 것만으로 에이전트 생성 도구가 추가되지는 않습니다.

## 사용 예시

### 요구사항부터 구현까지

```text
0-deep-interview → 1-prd → 3-build 순서로 사용해줘.
개발 시간은 3시간이야. 먼저 아래 문제 설명과 기존 코드를 확인해줘.
질문은 전체 최대 4개로 지정하고, PRD는 약 100줄로 정리해줘.
필수 기능을 먼저 완성하고 마지막 약 20%는 검증에 사용해줘.
구현까지 진행하고 실제 실행한 검증 결과를 알려줘.
[문제 설명]
```

### 서브에이전트 선택 사용

```text
4-delegate를 사용해줘.
gpt-6.1-sol 서브에이전트를 동시에 최대 3개 사용해줘.
추론 수준은 기본 medium, 복잡한 핵심 로직·검토는 high로 해줘.
실제 모델·추론 수준 지정과 동시 실행 지원을 먼저 확인해줘.
A는 프론트엔드, B는 분리된 핵심 로직, C는 읽기 전용 요구사항·테스트 검토를 맡아줘.
메인은 공용 계약 확정·진행 조정·통합·최종 검증을 맡아줘.
파일 수정이 필요한 추가 작업은 담당 파일이 겹치지 않을 때만 분리해줘.
도구가 없으면 메인이 순차적으로 진행해줘.
```

### 기존 명세가 있을 때

```text
3-build를 사용해서 docs/PRD.md의 필수 기능을 구현해줘.
기존 명세에 있는 내용을 다시 질문하지 말고,
실행 방법과 실제 검증 결과를 함께 정리해줘.
```

## 새 세션에서도 이어가기

각 스킬은 실제 서비스 프로젝트의 공통 상태·설정·단계별 인계 파일을 읽고 갱신합니다. 확정 결과를 다음 단계로 전달하고, 새 세션에서는 허용된 최신 파일과 코드를 대조해 이어갑니다. 전체 인터뷰 대화록을 복제하지 않습니다.

**5번 매뉴얼 검수는 확정 PRD·현재 구현·검증 결과를 기준으로 하며 초기 인터뷰·0번 인계·폐기 초안을 자동 참조하지 않습니다.** 자세한 경로와 재개 예시는 [SESSION_GUIDE.md](SESSION_GUIDE.md)를 확인하세요.

## 쉽게 수정하기

빠르게 / 표준 / 깊게 모드를 선택하거나 각 SKILL.md의 **조정 가능한 기본값**을 직접 편집하거나 호출할 때 값을 지정하세요. 사용자 지정과 플랫폼의 상위 규칙을 우선합니다.

| 조정 항목 | 기본값 | 변경 예시 |
| --- | --- | --- |
| 질문 예산 | 표준 최대 6개 | 빠르게 최대 2개 / 깊게 최대 12개 |
| PRD 분량 | 약 100줄 | 50줄 이내 |
| 작업 목록 | 보통 4~8개 | 5개 이하로 묶기 |
| 검증 시간 | 제한 시간의 약 20% | 마지막 40분 확보 |
| 동시 서브에이전트 | GPT 6.1 Sol 최대 3개, 메인 제외 | 실제 환경 한도 내에서 수·모델 지정 |

설정 파일이나 숫자를 읽는 프로그램은 없습니다. 이 값들은 모델이 따르는 자연어 지침이며 실행 환경에서 강제하는 하드 리밋은 아닙니다.

## 경량화 범위

- 작업마다 새 구현·리뷰 에이전트를 만드는 흐름을 생략했습니다.
- 전체 변경에 TDD를 강제하지 않고 핵심 동작과 회귀 위험에 맞춰 검증합니다.
- 문서는 PRD·작업 목록을 중심으로 간결한 검증 기록과 단계별 인계를 유지합니다.
- 반복 승인, worktree 구성, 장기 로드맵, 상세 보안 문서를 기본 절차로 넣지 않았습니다.
- 요구된 인증·권한, 비밀키 관리, 필요한 입력 검증은 해당 기능에 짧게 반영합니다.

별도 프레임워크를 설치하지 않아도 사용할 수 있습니다. 실제 코드 수정, 브라우저 확인, 테스트 실행, 에이전트 생성에는 해당 환경의 도구가 필요합니다. 이 스킬들은 권한이나 시험 규칙을 우회하지 않습니다.

## 검증 상태

기존 네 스킬과 추가한 두 스킬의 메타데이터·구조·내부 링크·라이선스 파일을 검사했습니다. 별도 에이전트로 PRD 작성 예시를 실행하여 질문 예산 재사용, 기능·제외 범위 보존, 완료 조건 작성, 문서 분량을 확인했습니다. 실제 Probe 환경에서의 가져오기와 서브에이전트 실행은 아직 검증하지 않았습니다. [검증 기록](VALIDATION.md)을 참고하세요.
